# CI: GitHub Actions

## Goal

Run the exact committed design baseline against an instrumented Vue 3 + Vite build, emit GitHub-native diagnostics and fail the PR on supported design mismatches.

## CI invariants

- no Figma request during `run`;
- no Figma token in normal PR CI;
- exact Node version pinned;
- exact npm dependency graph via `npm ci`;
- exact Playwright version/browser revision via lockfile;
- instrumented build uses `DESIGN_CONTRACT=1`;
- viewport/runtime values come from config;
- JSON artifact is generated even on design failure where possible.

## Recommended workflow

```yaml
name: Design Contract

on:
  pull_request:

permissions:
  contents: read

jobs:
  design-contract:
    runs-on: ubuntu-24.04

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Use Node 24
        uses: actions/setup-node@v4
        with:
          node-version: 24.19.0
          cache: npm

      - name: Install dependencies
        run: npm ci

      - name: Install pinned Chromium
        run: npx playwright install --with-deps chromium

      - name: Build instrumented app
        run: npm run build
        env:
          DESIGN_CONTRACT: "1"

      - name: Start preview
        run: |
          npm run preview -- --host 127.0.0.1 > /tmp/design-contract-app.log 2>&1 &
          echo $! > /tmp/design-contract-app.pid

      - name: Run Design Contract
        run: npx design-test run --no-start --reporter terminal,json,github

      - name: Upload Design Contract report
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: design-contract-report
          path: .design-contract/results.json
          if-no-files-found: ignore
          retention-days: 7
```

`design-test run --no-start` still performs its own base-URL readiness polling. The workflow therefore does not add a separate `wait-on` dependency. Because the CLI did not create this app process/build, the workflow is responsible for `DESIGN_CONTRACT=1` during build; after Vue Spike 2A the CLI verifies source metadata and fails `SOURCE_LOCATION_UNKNOWN` if the preview is uninstrumented.

## Build/start/wait semantics

### Install

`npm ci` must run from the committed lockfile.

### Browser install

`npx playwright install --with-deps chromium` installs the browser revision paired with the locked Playwright package and required Linux libraries.

### Build

The environment variable enables the Vite instrumentation plugin for this externally managed build only. When the CLI itself starts `app.command` in a normal local run, it injects the same variable automatically. `--no-start` cannot do that retroactively, so CI must set it while building/starting the external app.

A normal production build without the variable has no injected `data-design-test-source`.

### Start

Use `vite preview` to exercise the built instrumented assets rather than relying only on the dev server in CI.

### Wait

The CLI polls `app.baseUrl` until `startTimeoutMs`; then browser-level readiness uses `readySelector`, setup actions and font readiness.

### Run

No Figma token is supplied. A network attempt to Figma from `run` is a test failure in the Design Contract repository.

## GitHub annotations

The CLI emits workflow command annotations for each design difference with valid source ownership. GitHub renders them against PR files where paths/lines correspond to the checked-out revision.

## GitHub summary

The `github` reporter appends to the GitHub step summary using the standard summary file environment variable. It does not require API credentials.

## Artifact

The JSON report may be uploaded to the repository's GitHub Actions artifact storage through the explicit workflow step above.

This is not a Design Contract cloud upload. The host repository controls retention and can remove the upload step if policy requires no artifacts.

The report contains minimal findings including repo-relative source paths, Figma node IDs and expected/actual values. It does not contain source file contents, DOM HTML, screenshots, Figma raw JSON or access tokens.

## Secrets

Normal PR `run` requires no Figma secret.

If a repository creates a separate manual baseline-update workflow, it may provide `FIGMA_ACCESS_TOKEN` as a GitHub secret, but automated latest-Figma baseline updates are not recommended and must never happen as part of the normal PR gate.

Authenticated `storageState` should be generated/materialized by repository-controlled setup. Do not commit it by default and do not include it in artifacts.

## Caching

`actions/setup-node` npm caching may cache the npm download cache, not `node_modules`.

Do not cache Design Contract result JSON as a baseline.
Do not cache mutable Figma latest responses.
Playwright browser caching is optional; correctness must not rely on a cache hit.

## Failure behavior

- design mismatch → annotations + JSON + exit 1;
- config error → job error + exit 2;
- browser/app failure → job error + exit 3;
- internal defect → exit 4.

Artifact step uses `if: always()` so the semantic result survives a design-failure step when the file was successfully written.
